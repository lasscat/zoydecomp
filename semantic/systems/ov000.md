# ov000 object initialization / coordinate interface (unvalidated)

Question: which object defaults are unconditional, and which child setup depends on
the context/resource predicate? This is a DS-specific hypothesis, not a Board/Plant
mapping. No desktop source or layout was adapted.

The frozen uncompressed overlay maps ROM `0x00105c00` to VMA `0x021de5e0`, with
133216 stored bytes and 192 BSS bytes. The initializer at that entry has 508 code
bytes and a 12-byte referenced pool. ARM9 BL `0x02054350` reaches it, and its caller
consumes r0. **The first saved draft incorrectly leaves the return contract as void**;
it must not be used as a behavioral implementation or strict candidate.

Its direct coordinate helper at `0x021e0b7c` is 56 bytes, called at `0x021de6cc`.
It follows object+4/state+0x168, reads coordinates at +8/+0xc, adds 0x1d8 to x,
narrows to signed halfwords and calls ARM9 `0x02039734` with mode 0x5d/extent 0x50.
That external helper owns the output behavior; its signature is still provisional.

[Hash-bound records](../evidence/ov000-system-attempts.json) bind the saved drafts
and complete target blocks. They explicitly exclude these drafts from the canonical
644-candidate bank and all B/S/N/X counters. An early private initializer comparison
omitted its pool, so its apparent X classification is not admitted. A MWCC run failed
and was stopped; it was not a comparison. Warning-comment edits have not been re-probed.

A final bounded scope-proof attempt selected `0x021fd1ac`, a call-free 100-byte lookup
with two direct callers. Historical Clang/MWCC outputs were 108/92 bytes: neither
matched. Review then found a real source error: the selector belongs at record+0x10,
not +0x14. The banked lookup corrects that error but has not been compiled or tested.
The original-instruction harness stopped at unsupported `mvn r3,#0` before its first
case. It also needs its native return-pointer translation corrected. No completed
behavior cases or negative-control successes are claimed for any ov000 draft.

Totals: three fixed candidates, four compiler runs, zero exact matches, one compiler
failure, no repeated unchanged probes. **No overlay function passed the ROM gate.**
The strict overlay linker remains a mapping/section-plan prototype with synthetic
tests, not reconstructed overlay credit. Do not extend this into another leaf sweep.

Behavior is **blocked/not tested**: no original-instruction oracle spans the external
dependencies, and return/ownership/valid states remain unresolved. No sampled calls
